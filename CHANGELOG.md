# Changelog

Newest first. "Beta" means the skill is in `skills/in-progress`.

- `3.15.0`:
  - An improbable finding is no longer a blocker in `pr-review` or `refine`; it goes in the report as its line, and reviewers also list the pieces a change can lose. `strategic-programming` counts a case an untrusted party causes as live only when it gains them more than their access, or harms someone else.
  - Re-reviews cover what changed since the last review, and `refine` stops after three rounds even when told to keep going. `prototype` starts with two designers, and `writing-for-people` (beta) runs one cold read that also lists what to cut.
  - `adapt` (beta) is half as long and gives fresh reviews only to the parts that cross a one-way door or a guarded boundary. `shape` writes issues that say what must be true, not how.
  - `AGENTS.md` sets how a skill changes.
- `3.14.0`:
  - `adapt` (beta) runs the checks it can run with the access it already has. It asks the human once, and only when a check changes something, shows private data, or goes around a permission, approval, or audit log of the product.
  - `adapt` never skips a step of another skill on its own, and runs a command that waits for the human in the background.
  - `adapt` runs a task that is a list, such as a review's findings, from a tracking file that git ignores, one group at a time. At high stakes, a fresh agent reviews each group's plan before the human accepts it and its commits after. Only the human can lower or drop a reviewer's finding.
  - `strategic-programming` no longer treats a requirement as needed because an earlier issue recorded it. A requirement that needs machinery nothing else uses goes back to the human.
  - `program-design` is done only when the human accepts it on its `walkthrough` page. The spec and design templates say that an edit to a decision makes them a draft again.
  - In `adapt`'s plan mode, each slice of work says what must be true and leaves the mechanism to whoever designs it.
- `3.13.0`: `adapt` (beta) names a mode (build, fix, plan, or answer) after a first look, and sorts work that surfaces mid-task. It runs the gates of `architect` and `program-design` before its first stop, shows their results, and waits for the human to accept each design before building. It asks who implements a change that is costly to write.
- `3.12.0`: every piece must pass one test from `strategic-programming` before it is built: a live case gets the smallest piece, and an improbable case gets one line in the report instead. `adapt` (beta) does each kind of work through the skill that owns it.
- `3.11.2`: `adapt` (beta) checks each premise by reading or running the thing it is about before it relies on it. Documentation counts as a claim.
- `3.11.1`: `adapt` (beta) stops for the human before it builds whenever a decision is theirs, and puts everything the human must see in the message that ends its turn.
- `3.11.0`: adds `adapt` (beta), a user-invoked skill that designs a process for each task, as an alternative to `shape` and `deliver`. `strategic-programming` judges an existing pattern before it repeats it. `writing-for-people` (beta) puts the proof beside each claim and adds diagrams.
- `3.10.0`: `ship` waits for the review bot and answers a review with the smallest fix that closes each blocking item. `refine` considers undoing an earlier fix when it draws a new finding. `shape` lists what the spec adds beyond the request, for the human to keep or cut. `pr-review` (beta) reads the team's review guidance.
- `3.9.0`: `strategic-programming` adds a second opinion for every choice between designs, and `shape`, `program-design`, `refine`, and `deliver` use it.
- `3.8.0`: `writing-for-people` (beta) covers every text a person reads, and runs `unslop` after every edit.
- `3.7.0`: `pr-description` (beta) writes shorter descriptions.
- `3.6.0`: brings back `how` and `why` as stable skills.
- `3.4.0`: `shape`, `refine`, and `pr-review` (beta) work from the change's guarantees: what each person or system that depends on the change can rely on, and every link from where its data is made to where someone acts on it.
- `3.3.1`: `shape` treats the fix an issue proposes as a hypothesis, and starts its options with removing the cause.
- `3.3.0`: `pr-review` (beta) splits the review across up to three fresh reviewers, one per area, and adds two lenses: what can change between a check and the act that relies on it, and internal IDs or paths a stranger cannot read. `deliver` names acceptance tests without example IDs.
- `3.2.1`: `strategic-programming` fixes a defect at its root cause and handles a failure only when its cause is outside the system.
- `3.2.0`: adds `pr-review` (beta), which reviews a pull request as untrusted work before its human reviewer does. `ship` opens every pull request as a draft.
- `3.1.0`: adds `writing-for-people` (beta), which decides what a person needs from a text before it is written. `shape`, `deliver`, `grilling`, and `walkthrough` write through it.
- `3.0.1`: `program-design` observes, by running it, each existing behavior its design relies on. `shape` adds a fresh review of the spec against the code before acceptance.
- `3.0.0`: promotes `bug-hunt`, `program-design`, and `walkthrough` to stable, removes `how`, `why`, and `domain-language`, and lets agents invoke `wait-what`.
- `2.5.0`: adds `pr-description` (beta), which writes a pull request's description for its reviewer from the final diff, and checks each claim before publishing. `ship` uses it.
- `2.4.0`: `shape` splits work too large for one reviewable pull request into slices, each with its own issue and pull request. `ship` writes the description for the reviewer. `refine` blocks on a confirmed defect in any code the change touches, and adds lenses for deployment and documentation.
- `2.3.0`: adds `editor` (beta), an editor for articles and essays the user writes, in Spanish or English, that never writes the text for them.
- `2.2.0`: adds `walkthrough` (beta), which renders a design as a visual page, and `program-design` (beta), which settles the shape of the code before agents write it.
- `2.1.3`: a number a check imposes, such as a repetition count, states the outcome it protects and its measured cost, and goes to the human when evidence does not settle it. `shape` publishes what later work needs to the issue or the project's documentation.
- `2.1.2`: `architect` spikes every platform behavior its design relies on, and `shape` is done only when every fact the spec depends on is observed.
- `2.1.1`: `bug-hunt` (beta) hunts the whole project when given no area, and fixes every easy cause in one pull request.
- `2.1.0`: promotes `shape`, `deliver`, `refine`, `ship`, `garden`, `prune`, and `setup-verification` to stable, and adds `bug-hunt` (beta). `garden` and `prune` finish on their own.
- `2.0.4`: `shape` runs `architect` on every one-way door: persisted data or its schema, a contract that writes, a security boundary, or a seam an accepted ADR governs. `deliver` stops on a one-way door the spec does not settle.
- `2.0.3`: `deliver` asks every question in plain words with options and a recommendation. `shape` measures time budgets on the real target.
- `2.0.2`: a `writing-for-agents` pass over the delivery workflow that removes duplicated rules.
- `2.0.1`: `prototype` adds a scenario selector to every UI candidate.
- `2.0.0`: replaces the delivery chain with `shape`, `deliver`, `refine`, `ship`, `garden`, and `setup-verification`, built on examples that run as acceptance tests. It removes `feature-brief`, `implementation-spec`, `delivery-review`, and `product-validation`.
- `1.13.1`: merges duplicated rules into the skill that owns them. The catalog is about 700 words shorter.
- `1.13.0`: adds `prune` (beta), which retires tests and checks that no longer earn their cost.
- `1.12.3`: `deliver` loads `strategic-programming` and enumerates the state space of seams with interacting state.
- `1.12.2`: `deliver`'s close report names who accepted each residual risk.
- `1.12.1`: `delivery-review` repairs the findings you select through `deliver`'s repair loop.

- `1.11.0`: promotes the engineering skills to stable and adds `feature-brief` (beta).
- `1.10.0`: adds `prototype` (beta).
- `1.9.0`: adds `spike` (beta).

- `1.7.1`: the accepted architecture brief is temporary by default; ADRs are only for rationale that must last.
