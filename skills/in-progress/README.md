# In Progress

Public beta skills under evaluation. They are not promoted in the top-level catalog and may change or disappear without warning.

Install a candidate explicitly when one exists:

```bash
npx skills@latest add taecontrol/skills --skill=<name>
```

## Candidates

- **[`adapt`](./adapt/SKILL.md)** — User-invoked. Work one task through a process designed for that task, as an alternative to the fixed `shape` and `deliver` workflow, tried beside it. The agent reads first, questions the request and the existing code it would build on, and weighs the stakes, which set how much process the task gets. The human sees a message only when the agent ends its turn on it, so the agent stops before it builds whenever a decision is the human's: a choice between solutions, a change to something they decided and recorded, a fact only they hold, a different scope, or something hard to undo. Before it stops, it checks every premise the problem and the options rest on, by reading the code or system or observing it, and asks the human for any premise it cannot check. That message gives the decisions, the problem with what shows it, the solution beside the others it weighed, and where the work lands. When no decision is theirs, it writes them nothing and works. The contract, whose every line names a proof that fails when the line is false, and the route, with a reason per step, are the agent's notes. The final report carries the whole picture, with each detail the agent decided for them. The work can go to an implementer the user names, such as a cheaper model, through a brief that holds what will be verified and what the repository cannot tell. The designer runs each proof itself on the final state and names each finding's cause as guessed, ignored, or misled. Those causes, with the brief's size beside the change's, show whether the next brief needs more detail or less.
- **[`editor`](./editor/SKILL.md)** — Model-invoked. Be the user's editor while they write an article or essay themselves, in Spanish or English: from the idea through structure, draft, and edits to the final version. It diagnoses and the writer writes; its own words reach the piece only as the correct form of a sentence the writer tried and could not fix. Separate reader agents, each reading the draft cold, find the holes, and a notebook of the writer's recurring patterns carries what each piece teaches into the next.
- **[`pr-description`](./pr-description/SKILL.md)** — Model-invoked. Write or rewrite a pull request's title and description for a reviewer who knows the codebase but not how the change was made: why it exists, what changes, the decisions worth questioning, how to review it, and what was tested. The description is a map of the diff. It keeps only what changes how the reviewer decides, looks, or trusts, and points to the diff, the updated documents, and the tests for the rest, so a large change reads in about three minutes. Material from how the change was made becomes a statement about the code or goes to its own home. Before it is published, a fresh agent traces every claim to its source, flags anything the repository's visibility should not reveal, reads it cold against the diff, and lists what to cut. `ship` uses it, and it works on its own for any pull request.
- **[`pr-review`](./pr-review/SKILL.md)** — Model-invoked. Review a pull request, yours or someone else's, as untrusted work before its human reviewer does. It pins the head and the stack, runs the project's gates, lists every claim the change makes, and derives what the change guarantees and each guarantee's path to whoever acts on it. Then up to three fresh reviewers attack every link of those paths in parallel, one per area: failure and concurrency, trust and record, and contracts and design. Each reads the whole affected flow and the sibling code that does the same job, and checks that the tests catch the defects of its area, by mutation where it owns a link or a guard. The contracts and design reviewer reads the change as a stranger, without the spec. The agent running the review confirms each finding by reading or running, settles conditions from configuration, and lists every site of the same mechanism. The report opens with "This is a preliminary automated review." and ranks findings by consequence as Blocking, Should fix, Tests to fix or add, and Considered. It never approves or requests changes, and posts only when asked.
- **[`writing-for-people`](./writing-for-people/SKILL.md)** — Model-invoked. Decide what a person needs from a text before writing it, for any text a person reads: a message or report to the user, or text other people read, such as an issue, comment, ticket, pull request, document, README, slide, UI copy, or a message to a colleague. It leads with what the reader came for, explains every ID and term where it appears, puts the proof beside each claim the reader will act on, gives the reason behind each decision, keeps process material out, and ends with `unslop`, loaded as a skill and run again after every edit. Before text leaves the conversation, a fresh agent reads it cold and reports every term it cannot resolve and every question it would ask. `wait-what`, `shape`, `deliver`, `spike`, `garden`, `grilling`, `walkthrough`, `pr-review`, and `pr-description` write through it.
